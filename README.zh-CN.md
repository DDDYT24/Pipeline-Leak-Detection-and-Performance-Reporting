# Pipeline Leak Detection and Performance Reporting

[English](README.md) | [简体中文](README.zh-CN.md)

**管道泄漏检测与性能报告**：一个 Python 工程项目，研究液体管道的质量平衡、测量不确定性，以及评价泄漏检测判断所需的证据。

## 项目初衷

入口与出口流量的差异可能来自泄漏，也可能来自测量噪声、仪表偏差，或管道运行过程中内部储存量的变化。有用的监测系统需要区分这些情况，并说明判断的适用范围。

本项目围绕三个实际工程问题展开：

- 平滑处理能够减少哪些短暂的测量扰动？哪些持续性误差仍然存在？
- 增加报警的持续性要求，会带来多少检测延迟？
- 为什么缺失或可疑的仪表数据必须显示为“不可评价”，而不能显示为“运行正常”？

这些问题构成了项目的研究方向。当前实现提供工程计算与可复现的测量数据基础，尚未得出经过实验验证的检测性能结论。

## 事故背景

2010 年 7 月 25 日，Enbridge Line 6B 在美国密歇根州 Marshall 附近发生破裂，当时正处于计划停机的最后阶段。NTSB 调查记录显示，破裂超过 17 小时未被发现或处理，随后两次启动造成的释放量占总量的 81%。这一案例说明，在运行状态变化期间，正确解释异常和关注响应延迟十分重要。[NTSB 调查](https://www-s.ntsb.gov/investigations/Pages/DCA10MP007.aspx)

PHMSA 将体积平衡、质量平衡、参数变化率和计算管道监测（Computational Pipeline Monitoring，CPM）列为泄漏检测方法，并指出其有效性取决于管道、输送介质、仪表及运行条件。[PHMSA 泄漏检测概述](https://primis.phmsa.dot.gov/stakeholder-comms/factsheets/fsleakdetectionsystems/)

事故资料用于解释工程问题的背景。项目生成的测量数据既不是该事故的重建数据，也不是任何运行管道的真实记录。

## 已实现功能

- 通过配置文件驱动水平、单相液体管道的工程计算。
- 计算流速、雷诺数、Darcy 摩擦系数、摩擦压降和质量流量。
- 在管道中点设置指定泄漏流量，并保持两段管道之间的质量守恒。
- 生成可复现的正常运行、2% 泄漏和 5% 泄漏场景，加入独立的测量噪声。
- 分别导出测量数据、回放元数据和事件真值 CSV。
- 生成导出清单，记录模型假设、配置、软件包版本和数据行数。
- 自动检查工程参考值、守恒关系、可复现性和无效输入。

当前仓库包含数据生成与流体计算基础。此版本尚未包含检测算法、事件级性能指标或 Power BI 报表文件。

## 数据流程

~~~text
管道及场景配置
    → 稳态物理状态
    → 含噪声的仪表测量
    → CSV 数据与来源清单
~~~

测量数据可以导入 Power BI Desktop。Python 负责工程计算，CSV 接口将计算分析与报表展示分开。

## 模型与单位

模型采用一根水平、等直径管道，输送密度和黏度固定的单相液体。不考虑高程变化、支路、管件局部损失、中间泵站或瞬态储存量变化。

输入流量以 m³/h 表示，计算时转换为 m³/s：

~~~text
A = πD² / 4
v = Q / A
Re = ρvD / μ
ΔP = f_D (L/D) ρv²/2
ṁ = ρQ
~~~

其中 A 是截面积，D 是管径，v 是流速，Q 是体积流量，ρ 是密度，μ 是动力黏度，L 是管长，f_D 是 Darcy 摩擦系数，ΔP 是摩擦压降，ṁ 是质量流量。

摩擦系数使用 Darcy 定义。层流采用 64/Re，湍流采用 Haaland 近似式。过渡流状态会被拒绝，避免给出没有适用依据的计算结果。停止流动时，摩擦压降为零。

指定泄漏在管道中点抽取流量。入口流量固定，出口压力固定，两段管道分别使用各自的流量计算摩擦压降：

~~~text
Q_in = Q_out + Q_leak
~~~

这是指定泄漏流量的稳态模型，不是泄漏孔口模型或瞬态压力波求解器。合成泄漏时间表发生突变时，模型直接切换稳态，不求解真实的过渡过程。

## 复现数据

在 Windows 上使用 Python 3.14 复现锁定的依赖环境。项目已使用 Python 3.14.5 验证。以下命令在项目根目录的 PowerShell 中执行：

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pipeline_leak_detection --config configs/starter.json
.\.venv\Scripts\python.exe -m pytest -q
~~~

默认导出目录为 data/generated。再次运行生成器会替换该目录中的已生成 CSV 和清单文件。生成结果和本地 Python 环境不纳入版本控制。

| 文件 | 每行代表什么 | 内容 |
| --- | --- | --- |
| readings.csv | 一个回放中的一个采样区间 | 含噪声的流量和压力、质量流量不平衡量、仪表状态 |
| runs.csv | 一个回放 | 随机种子、配置版本、合成日期、标称流体计算值 |
| truth.csv | 一个合成泄漏事件 | 开始与结束时间、实际指定泄漏流率、释放体积 |
| manifest.json | 一次导出 | 数据来源、模型假设、完整配置、依赖版本、行数 |

默认配置生成三个各持续两小时的回放，每十秒采样一次，共 2,160 条测量记录。时间戳为合成时间，采用 UTC。区间包含起始边界，不包含结束边界。回放元数据和事件真值与测量数据分开保存；这些演示数据不属于独立留出的评估数据集。

## 验证

九项自动检查覆盖：

- SI 单位转换与标称流体计算参考值。
- Haaland Darcy 摩擦系数与 fluids 库摩擦系数计算的对比。
- 管道中点质量守恒与压力大小关系。
- 零噪声条件下测量数据与独立事件真值的一致性。
- 随机种子可复现性与回放时间戳唯一性。
- 无效几何参数、泄漏流率和非完整采样区间。
- 停流与层流的处理。

标称示例使用假设参数：管长 10 km、管径 0.4 m、密度 850 kg/m³、动力黏度 0.005 Pa·s、粗糙度 0.000045 m、流量 800 m³/h。计算结果约为：流速 1.768 m/s、雷诺数 120,250、摩擦压降 0.589 MPa。

这些检查验证了实现与所述假设的一致性，不能证明算法在真实运行管道上的泄漏检测性能。

## 解释与使用限制

所有生成数据均为使用假设参数构造的合成数据。项目没有连接任何运行管道或控制系统。

一般情况下，入口质量流量减去出口质量流量，同时包含可能的泄漏流量和管内储存质量的变化率。当前稳态模型将储存量变化率设为零，因此不能在启停期间将该差值直接视为确定的泄漏估计。

各测量通道来自同一个简化物理数据生成器，它们之间的一致性不能代替独立的现场验证。项目不宣称已完成现场部署、工业调试或符合行业标准。
